# DeepSeek Harness Mobile v1.0.4

## What's changed

- Matched the Harness Web workspace folder and disclosure icons in the mobile drawer.
- The current session's workspace now appears blue and expanded; other workspaces are gray and collapsed by default.
- Workspace headers remain interactive, so another workspace can be expanded before selecting one of its sessions.
- Selecting a session updates the active workspace state immediately and collapses the previous workspace.
- Replaced the wrench used for Context injection activity with the exact document-style icon from Harness Web.
- New Session now creates directly in the current session's workspace instead of showing an Android directory-selection dialog.
- Sessions outside a registered workspace continue to use Harness's default ungrouped directory behavior.
- The Commands menu's `plan` action now inserts `/plan` into the composer, matching Harness Web, instead of opening a native Android mode picker.
- Added task-completion notifications that keep monitoring a user-started Harness run after the app moves to the background.
- Running tasks use Android 16 `ProgressStyle` and request promoted Live Update treatment; Pixel 10 grants `PROMOTED_ONGOING`.
- When a task completes, the existing Live Update stays on the same channel and transitions to 100% with `✅ 已完成`, the Session name, and a cleaned excerpt from the beginning of the final assistant reply; the completed Fluid Cloud state remains visible briefly before timing out.
- Tapping a completion notification opens the matching Session, and canceled/failed turns without a new final reply are not mislabeled as completed.
- Added notification permission onboarding and a quiet Live Update channel shared by the running and completed states, so completion no longer falls back to a separate ordinary-notification channel.
- Rebuilt the mobile drawer header and toolbar from the official Harness wordmark, icons, colors, dimensions, and spacing, with a 264 dp reference-width cap on larger phones.
- Replaced ColorOS's fallback paper-plane progress marker with the official Harness whale logo across running and completed Fluid Cloud states.
- Fixed command-menu permission changes so they execute through Harness's host `commands/execute` path, update the Access chip, and never become a user message or trigger a model reply.
- Matched the complete Web command menu: compact executes immediately, export downloads immediately, feedback/goal/plan populate the composer, permission opens the Access picker, and the mobile-only model entry was removed.
- Added Harness Web-style Appearance preferences with Light, Dark, and System options. The selection persists across restarts, System follows Android configuration changes, and existing installs retain the current Dark appearance until the user chooses otherwise.
- Added a semantic light palette across the conversation, composer, sidebar, menus, dialogs, code surfaces, notices, approvals, and system bars; the light drawer uses a theme-aware Harness wordmark instead of losing the white logo on a white surface.

## Compatibility

- No private or project-specific server address is embedded in the app or these notes.
- The app connects only to a Harness server configured by the user.
- Android 8.0 (API 26) or newer is required.
