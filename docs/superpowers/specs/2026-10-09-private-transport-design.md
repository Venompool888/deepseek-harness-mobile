# dshbridge 服务端与 Android 客户端设计

设计日期：2026-10-09。状态：本轮实现与本机验证已完成，尚未部署公网；2026-10-10 补充服务端命名。

## 两个服务端的命名

**dsh 服务端**是 DeepSeek Harness 原生服务，负责模型调用、任务执行、会话与原生 Web；**dshbridge 服务端**是本规格的自研 Go 通信壳，负责设备认证与传输转发。当前方案让两个独立组件同机运行。本文的外层服务、配对、设备 token 和随机路径均属于 dshbridge；内部上游和原生启动 token / Cookie 属于 dsh。完整区分见 [服务端职责说明](../../architecture/server-roles.md)。组件名是 dshbridge，现有 CLI 文件名仍为 `dsh-bridge`。

## 已确认目标

用户要求公网不直接暴露 dsh Web 的页面和接口特征。Android 保留 dsh 0.2.0-rc.2 的业务协议，在客户端和 dshbridge 服务端增加自己的认证及传输封装。外层不是新的聊天业务 API，dshbridge 服务端不重新解释会话状态或生成自己的聊天事件。

本轮不实现 NaïveProxy、不模仿浏览器网络栈、不承诺消除 TLS 或流量统计特征。

## 部署假设

第一版按 dshbridge 服务端与 dsh 服务端同机运行设计，支持 Windows、macOS 和 Linux。dsh 服务端只监听回环地址，dshbridge 是唯一公网应用入口。公网中转连接家中电脑涉及另一个出站连接子系统，不纳入本轮。

公网必须使用 HTTPS/WSS；TLS 可由 dshbridge 或常规反向代理终止。代理只转发到 dshbridge，不能配置到 dsh 的直通路由。开发和 Pixel USB 测试允许明确的回环 HTTP，不能以此替代公网 HTTPS 验收。实现与本机真机验证不包含实际发布公网服务或修改防火墙。

## 方案选择

采用固定 HTTPS 请求入口加固定 WSS 流入口，内部载荷保持 dsh 协议。这比任意 TCP/CONNECT 隧道更容易限定目标和控制资源，同时保留现有 RPC、Remote mux 和状态合并代码。

不采用普通 dsh 路由反向代理，因为它会将原始页面、路径或重定向暴露到公网。不采用业务协议转换，因为它违背用户保留 dsh 协议的要求，并增加跟随官方版本的成本。

## 组件与数据流

Android 界面 → 现有 dsh 编解码及状态层 → 自有传输层 → HTTPS/WSS → dshbridge → 回环 dsh 服务端。

dshbridge 服务端使用 Go 实现，可构建各桌面平台的独立可执行文件。配置只包含监听地址、TLS 方式、固定 dsh 服务端回环地址、dshbridge 服务端保存的 dsh 启动凭据和凭据存储位置。用户可自行启动 dsh；本轮不做 Desktop 注入、安装器或进程自动管理。

dshbridge 服务端只访问配置好的 dsh 服务端回环 origin，拒绝上游重定向和客户端指定的目标地址。接入 dsh 的启动 token 由 dshbridge 服务端在内部兑换 authority 对应的 Cookie，认证失效时报告上游不可用，不把 dsh 登录链接发给手机。公网认证凭据和内部 dsh Cookie 分开管理。

## 外层协议 v1

用户追加要求：每个部署使用不同的随机公网路径，内部保留稳定的功能名称及映射文档。以下名称是逻辑入口，不注册为固定的公网 `/v1/*` 路由，也不公开映射成 `/api/<dsh-method>`：

- `pair`（POST）：用一次性配对凭据注册设备。
- `rpc`（POST）：请求体就是现有 dsh `client-request` 信封；dshbridge 服务端验证 method 在明确支持的清单内，再发往内部对应路由。成功响应保留原始 dsh RPC 信封和 rpcId。
- `stream`（GET / WebSocket）：验证设备凭据后才升级 WebSocket，建立专属的内部 `/api/remote.mux` 连接。保留原始 open/cancel、item/error/end 帧、streamId 及事件相关性；检查打开的 endpoint 在支持清单内。不同设备和物理连接不共享内部 mux。
- `export`（POST）：只接受 sessionId 和 includeDescendants，流式转发指定会话导出。下载不跳转到 dsh URL，不透传内部 Cookie 或路径。

### 每部署路径映射

首次初始化为四个入口分别用密码学安全随机源生成路径，每条路径包含至少 128 位随机量，以 URL 安全字符组成两个段；不带产品名、功能名称或协议版本。映射写入 dshbridge 服务端私有配置 `routes.json`，作为实际路由注册和本地维护命令的唯一依据。稳定逻辑名称映射到随机路径，例如 `rpc → /fahoifha/fjwapofa`；此短例只用于说明，不代表实际生成长度。协议版本独立存储为 `protocolVersion: 1`。

映射持久保存，重启和升级不重新生成。配置缺失或损坏时停止启动并提示本地管理员恢复，不悄悄生成另一套路径。映射不得通过公网根页面、公开文档、无认证发现接口、响应头或重定向发布，也不提交实际部署映射到仓库。

本地管理命令显示逻辑入口、HTTP 方法和真实路径，文档说明每个逻辑入口的用途；文档与运行配置不维护两份独立路径清单。导出的配对连接资料包含 origin、协议版本和随机 pair 路径，一次性配对凭据在请求正文提交。成功配对后通过 TLS 返回该 origin 下的 rpc、stream、export 相对路径，手机校验并按服务器保存。只允许纯相对路径，不允许跨 origin 地址、查询串或片段。

路径更换作为显式维护操作，需要重新分发连接资料并重新配对；本轮不做自动轮换或旧路径兼容。恢复备份应包含映射配置。随机路径减少固定路由线索，不替代认证，也不保证流量不可识别；已配对设备可以知道真实路径。

HTTP/WS 的认证在进入 dsh 前完成。dshbridge 服务端保留已认证的业务载荷，包括原始 dsh 业务错误；外层网络、认证和上游连接错误使用我们自己的稳定错误码。外层协议变化需版本号，不能用改名操作破坏 dsh 信封格式。

不提供 dsh HTML、JS/CSS、favicon、WebView 跳转、任意文件或任意路径转发。公网根路径、未知路径、固定 `/v1/*`、`/api/*` 和无效认证的真实路径返回统一的空 404；认证先于业务解析和 WS 升级。已认证客户端才获得具体的外层业务错误。错误响应、响应头和重定向不包含 dsh 版本、产品名、token、Cookie 或内部地址。统一内容不承诺响应时延完全一致；不能只靠隐藏按钮满足此要求。

已认证设备可操作此 dsh 实例的受支持功能。本轮是个人使用、单实例模型，不承诺多用户会话隔离。支持清单覆盖当前原生客户端所使用的 RPC 和逻辑流，排除未使用的 Web 管理入口；添加功能时显式更新清单。

## 设备认证

dshbridge 本地管理命令生成短期、一次性的高熵配对凭据，供用户复制到手机。凭据不放在 URL 查询参数中；有效期 10 分钟，成功兑换后立即作废。公网不允许匿名生成配对凭据。

配对成功返回随机的 256 位设备 token，之后通过 Authorization 请求头认证 HTTP 和 WebSocket。dshbridge 服务端只保存 token 摘要、设备标识及撤销状态；手机使用 Android Keystore 保护持久凭据，按 dshbridge origin 隔离。配对接口按来源限速，HTTP 正文与 WS 消息均设大小上限。

dshbridge 本地管理命令支持列出和撤销设备。撤销立即阻止新请求并关闭该设备已有流连接；在途请求不保证回滚已被 dsh 接受的操作。配对凭据、设备 token、内部 dsh 凭据、聊天正文及原始帧不进入默认日志。

## Android 改动边界

抽出单次 RPC、物理流连接、导出和认证的传输接口；保留 HarnessRpc、RemoteStreamRouter、HarnessSessionState、HarnessRemoteEvents 等业务协议与状态代码。前台、TaskMonitorService 后台任务读取和导出统一使用选定传输，不能残留直连路径。

保留已有直连配置供本地开发和旧连接使用，新增明确的 dshbridge 连接类型。dshbridge 连接失败不会自动回退直连 dsh。dshbridge 模式不打开官方 Web 管理入口；用户可在运行 dsh 服务端的电脑本地使用 Web。

私有连接页展示 dshbridge 地址、配对凭据输入、已配对设备及撤销/过期错误；配对成功后清除输入。前端设计继续交由 agy-subagent 工作流，dshbridge 服务端与协议工作由 Codex 负责。保持现有 Kotlin Views 和 Material 主题。

## 断线与资源生命周期

外层断开即关闭对应内部 mux，取消尚未完成的读取和转发，使用有界缓冲并保持帧顺序；慢客户端触发明确关闭，不能无限积压。限制每设备连接数与并发请求数。

重连仍沿用 dsh 的权威快照恢复。原始 rpcId、提示请求身份、审批事件身份和帧序号不得在外层重写。dshbridge 服务端不自动重试发送、停止或审批等业务变更；手机继续处理“结果未知”，避免重复提交。设备撤销或内部认证失效不会伪装成业务成功。

## 验收条件

1. 无认证探测公网根路径、dsh API 路径、固定 `/v1/*`、真实随机路径、Web 静态资源和错误路径，得不到 dsh 页面、重定向、Cookie、版本或原生路由响应；RPC/WS 拒绝发生在上游访问之前。两个独立初始化产生不同映射，重启与升级保持原映射；手机从配对响应取得路径，拒绝跨 origin 映射。
2. 配对过期、重复兑换、错误凭据和撤销可测；撤销已连接设备会关闭其流。日志与错误响应不包含凭据。
3. RPC 信封、标量/数组/null 结果及业务错误保持兼容；WS 帧序列、逻辑流取消和不同设备连接隔离有集成验证。
4. 客户端不能改变上游地址或访问清单以外的路径；导出只允许指定会话操作，不转发内部响应头。
5. 断线、上游故障、慢客户端和客户端关闭会释放资源，不自动重复业务提交；流重连恢复现有会话状态。
6. 本机真实 rc.2 加 Pixel 10 验证配对、列表、聊天流、停止、审批、后台通知和导出。另以本地 TLS 测试验证 HTTPS/WSS 认证，USB 明文验证不能替代 TLS 验证。
7. Android 构建、相关单元测试和 lint 通过；Go dshbridge 服务端单元及集成测试通过，并完成三平台交叉构建。未在对应实体系统运行的产物明确标记为仅交叉构建。

## 与已完成适配的关系

本规格是在 rc.2 原生适配之上增加传输壳，不废弃已有协议工作，也不宣称此前直连已满足新的公网目标。仓库既有包名迁移、OAuth、主题及 rc.2 适配修改均须保留，只提交本轮明确文件。
