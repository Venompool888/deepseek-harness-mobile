# dsh rc.2 Android Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development only if the user selects that execution method. Steps use checkbox syntax. Frontend design is delegated to agy through the user-selected agy-subagent workflow.

**Goal:** Make the existing native Android client's connection, core chat, live state, approvals and background notifications work with dsh 0.2.0-rc.2.

**Architecture:** Keep the existing Views UI and useful HarnessApi DTOs. Isolate connection parsing/authentication, unary Remote RPC, physical mux and session state reduction into focused units; the Activity and notification service consume the same adapter. Use exact tagged Web source as protocol authority and agy's reviewed design as UI authority.

**Tech Stack:** Kotlin, Android Views/Material Components, existing OkHttp and org.json, JUnit 4, current Gradle configuration. No Compose migration and no additional production dependency by default.

**Spec:** [Approved core adaptation spec](../specs/2026-10-09-dsh-rc2-core-design.md).

## Global Constraints

- Target is official `dsh-v0.2.0-rc.2`; no promise of old-protocol or Alpha compatibility.
- Preserve all existing user changes, including package migration, OAuth and themes. Current product package is `app.deepseek.harness.mobile`; do not change applicationId.
- Keep Android API 26 minimum and the existing Views architecture.
- Public addresses require HTTPS; HTTP remains limited to supported private-network addresses.
- Save clean server addresses. Launch token is only for index authentication, never for business RPC, WebSocket URLs, export URLs or logs.
- Keep Cloudflare Access and Harness authentication distinct; neither replaces the other.
- Do not automatically broaden server listen addresses, trusted-host rules or public exposure.
- Chinese/English, light/dark, 48dp touch targets, keyboard insets and old-message reading position remain supported.
- No new plugin manager, terminal, attachments, schedules, goal editor, plan review or question composer.
- agy owns frontend design. Any frontend implementation delegation requires an explicit task contract, scoped permissions and diff review; do not let agy edit protocol files.
- Codex subagents must use GPT-6/6.1 family models. The agy liaison uses `gpt-6-luna` with `max`, overriding the skill's obsolete GPT-5 entry.

## Review Focus

1. A valid local URL carries duplicate/empty token parameters: reject without contacting the server or retaining a token.
2. A server changes origin during login: do not forward either Access credentials or Harness cookies to the new origin.
3. A late stream callback follows a session/server switch: ignore it, including approval and connection-error callbacks.
4. A send times out after server acceptance: preserve draft and reconcile history; never blindly resend the prompt.
5. A pending approval is resolved on Desktop during mobile reconnection: recover authoritative state and never submit the stale approval.

Each condition has a test in its owning task below.

## Task 2: Import launch links and establish Harness authentication

**Interfaces:**

```kotlin
internal data class ServerConnection(val origin: String, val launchToken: String?) {
    companion object { fun parse(input: String, language: AppLanguage): ServerConnection }
}
internal enum class ConnectionFailure { NETWORK, AUTH_EXPIRED, ACCESS_FORBIDDEN, INCOMPATIBLE_PROTOCOL }

```

HarnessAuthentication implements HarnessAuthHeaders. Its exchange method accepts ServerConnection and the existing external authentication provider, uses a GET to the same root authority and stores accepted cookies through the app's existing local CookieManager owner. ## Task 4: Implement logical Remote streams and session state repair

**Files:** Create `HarnessRemoteMux.kt`, `HarnessSessionState.kt`, corresponding tests; modify `HarnessApi.kt` and Activity's current stream lifecycle.

**Interfaces:**

```kotlin
internal interface RemoteStreamHandle { fun cancel() }
internal interface RemoteStreamListener {
    fun item(value: JSONObject)
    fun failed(code: String, message: String)
    fun ended()
}
internal interface HarnessRemoteStreams {
    fun open(endpoint: String, args: JSONObject, listener: RemoteStreamListener): RemoteStreamHandle
    fun close()
}
internal data class SessionGeneration(val connection: Long, val selection: Long)
```

HarnessRemoteMux implements HarnessRemoteStreams with one authenticated `/api/remote.mux` socket. Opening sends `{type:"open",streamId,endpoint,payload:{args}}`; cancel sends `{type:"cancel",streamId}`. Accept item/error/end only for a live streamId. Core session stream items use the actual tagged snapshots/journal/assistant schemas, not the legacy event payload.

- [ ] Add reducer tests from fixtures: baseline replacement, one append, duplicate append, cursor gap, assistant revision mismatch, completion, late items from previous connection and previous session selection.
- [ ] Implement a reducer whose updates require matching SessionGeneration. A gap invalidates the stream and triggers fresh follow snapshot; no out-of-order partial output is silently appended.
