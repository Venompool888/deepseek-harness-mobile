# Android 原生客户端适配 dsh 0.2.0-rc.2 前端交互与视觉设计规格 (design.md)

- **目标版本**: dsh 0.2.0-rc.2（严格针对 rc.2 目标协议，不承诺后续版本兼容）
- **阶段**: 前端设计阶段 (Design Only - 仅限界面交互、视图规范与视觉设计，不修改 Kotlin/XML 源码)
- **目标平台**: 原生 Android (基于现有 Material 3 Views 体系与 DayNight 主题，基准适配 411dp 紧凑型手机屏幕)
- **数据声明**: 本设计及配套预览原型中所有数据、会话及凭据均为**合成模拟数据 (Synthetic Mock Data)**，不接入真实服务，不反映或执行任何真实服务器状态。
- **文档语言**: 中文 (交互文案支持中英双语定义)

---

## 1. 设计概述与设计哲学

### 1.1 核心目标
本设计针对自托管 DeepSeek Harness (dsh 0.2.0-rc.2) 核心体验进行 Android 原生客户端的前端交互与视觉定义：
1. **保持原生质感与产品辨识度**：延续 DeepSeek Harness 经典的蓝黑专业基调、信息紧凑感和“看得到 Agent 工作过程”的产品特色。
2. **连接导入体验平滑升级**：支持标准服务器地址与带启动 Token 的链接导入，在客户端进行安全校验并向用户呈现温和的人性化引导。
3. **消除内部协议黑话**：所有用户可见文案严禁出现底层协议术语（如 Mux、RPC ID、WebSocket 帧、信封结构、Cookie 兑换等），转化为清晰的人机状态描述。
4. **精细化认证与异常恢复**：明确区分外层网络访问验证（如 Cloudflare Access）与 Harness 本地认证过期；针对 Harness 凭据失效引导用户提供新的启动链接，而非笼统的“重新登录”。
5. **原生 Android 交互与工程落地**：严格基于现有 Android Views 架构与 Material 3 体系，规范 48dp 最小触控区域、键盘弹起位置记忆、大字体排版与屏幕阅读器无障碍（a11y）标签。

## 2. 视觉规范与设计系统 (Design System)

### 2.1 基准屏幕与布局参数
- **基准视口**: 宽 411dp（主流紧凑型 Android 手机标准宽度，如 Pixel 7/8、OPPO 系列）。
- **最小触控目标**: 所有交互控件、图标按钮、弹窗操作项均满足 ≥ 48dp × 48dp 触摸热区（或包含对应 padding 的触控代理）。
- **圆角体系 (Corner Radii)**:
  - 小组件 (Chip / 输入框 / 菜单项): 8dp ~ 10dp
  - 中组件 (卡片 / 弹窗操作钮 / 抽屉项): 14dp ~ 18dp
  - 大组件 / 气泡 (审批卡片 / 用户消息气泡 / 底部输入框外壳): 20dp ~ 24dp
  - 药丸钮 / 圆形操作钮 (发送/停止钮、状态标签): 22dp ~ 24dp (完全圆角)

### 2.2 调色板映射 (DayNight 规范，与现有 AppPalette 对齐)

## 3. 概念状态模型与人机交互映射

### 3.1 连接生命周期与错误反馈 (`ConnectionPhase`)

```
   ┌───────────────┐
   │  未配置地址   │ ◄── 首次启动 / 手动清除
   └───────┬───────┘
           │ 用户输入地址或粘贴启动链接，点击“连接”
           ▼
   ┌───────────────┐
   │  正在连接…    │ ─── 验证服务器可达性与认证通道
   └───────┬───────┘
           ├───────────────────────────────┬──────────────────────────────┐
           ▼                               ▼                              ▼
   ┌───────────────┐               ┌───────────────┐              ┌───────────────┐
   │  需要身份验证 │               │    已连接     │              │   连接失败    │
   └───────┬───────┘               └───────┬───────┘              └───────┬───────┘
           │ 完成登录/提供新链接           │ 网络波动                     │ 点击“修改”重试
           └──────────────────────────────►│◄─────────────────────────────┘
                                           │
                                           ▼
                                   ┌───────────────┐
                                   │  正在重新连接 │
                                   └───────────────┘
```

#### 连接状态定义与文案规范

| 概念阶段 (`ConnectionPhase`) | 状态指示器外观 | 中文显示文案 | 英文显示文案 | 界面行为与说明 |
| :--- | :--- | :--- | :--- | :--- |
| **未配置** (`unconfigured`) | 灰色圆点 | 未配置 | Not configured | 顶部显示“未配置”，点击弹出连接配置对话框。 |
| **验证中** (`validating`) | 蓝色转圈 / 琥珀色微光 | 正在连接… | Connecting… | 禁用“测试并连接”按钮，输入框置灰，反馈验证中。 |
| **需外部访问验证** (`cfAuthRequired`) | 琥珀色实心点 | 需要访问验证 | Access verification required | 提示需要完成外部访问网关验证（如 Cloudflare Access），打开验证通道。 |
| **Harness 凭据失效** (`authExpired`) | 琥珀色实心点 | 连接凭据已失效 | Connection credentials expired | 提示 Harness 启动凭据失效，引导用户重新提供带有令牌的有效启动链接。 |
| **已连接** (`connected`) | 绿色实心点 | 已连接 / 运行中 | Connected / Running | 恢复会话历史与状态流，输入框可用。 |
| **重新连接中** (`reconnecting`) | 琥珀色脉冲点 | 正在重新连接… | Reconnecting… | 顶部黄色横幅弱提示，保留当前消息，自动静默同步。 |
| **连接失败** (`failed`) | 红色实心点 | 连接失败 | Connection failed | 顶部红色状态点，错误提示条展示人本错误与“重试/设置”。 |

#### 错误类别 (`ConnectionFailure`) 与面向用户的反馈
所有错误严禁展示底层技术堆栈或协议术语：
1. **网络不可达 (`network`)**
   - 中文：“无法连接到服务器，请检查网络连接或服务器地址是否正确。”
   - 英文：“Unable to reach the server. Please check your network or server address.”
2. **Harness 连接凭据过期 (`authExpired`)**
   - 中文：“Harness 连接凭据已失效，请从桌面或命令行重新获取启动链接。”
   - 英文：“Harness connection credentials expired. Please provide a fresh startup connection link.”
3. **外部访问网关过期/未授权 (`accessForbidden` / `cfExpired`)**
   - 中文：“访问通道已过期或未授权，请完成身份验证。”
   - 英文：“Access verification required. Please complete sign-in.”
4. **服务器版本不匹配 (`incompatibleProtocol`)**
   - **严格约束**：必须明确指明目标适配版本为 rc.2，提示用户核对服务器与客户端版本，严禁承诺“0.2.0-rc.2 或更新版本”！
   - 中文：“当前服务器版本与客户端不匹配。本版本仅适配 dsh 0.2.0-rc.2，请检查服务器与客户端版本。”
   - 英文：“Incompatible server version. This client targets dsh 0.2.0-rc.2. Please check server and client versions.”

### 3.2 启动链接与地址导入安全交互

#### 用户输入模式
1. **常规地址输入**: 用户输入 `https://harness.mycompany.com` 或内网 `http://192.168.1.100:3080`。
2. **快速启动链接导入**: 用户直接粘贴从桌面端或命令行获取的带有临时通行令牌的完整 URL（如 `http://192.168.1.50:3080/?token=abc123xyz...`）。

#### 前端交互规则与隐私保护
- **即时解析反馈**: 当输入框检测到包含启动 Token 时，输入框下方出现蓝色提示胶囊：“已识别快速启动链接，将在连接时自动换取访问凭据”。
- **地址清洗与保存**: 连接成功后，输入框及已保存连接列表中仅展示干净的服务器主地址（如 `http://192.168.1.50:3080`），**绝不将 Token 长期保存在文本框中或向外展示**。
- **参数限制提示**: 若用户粘贴带有非法查询参数或多余路径的链接，红字清晰提示：“链接包含不受支持的参数，请仅使用标准服务器地址或启动链接”。
- **网络协议保护**:
  - 公网域名必须强制使用 HTTPS。
  - HTTP 仅在合法私有内网 IP（如 `127.0.0.1`、`192.168.x.x`、`10.x.x.x`、`172.16~31.x.x`）或 `.local` 时放行，否则明确提示阻拦。

## 4. 核心界面设计与模块规范

### 4.1 顶部栏 (Top App Bar & Header)
- **高度**: 56dp。
- **左侧**: 侧栏抽屉开关按钮（图标 `☰`，48dp 触控区域），无障碍描述：“打开侧栏”。
- **中间**:
  - 主标题：当前会话标题（单行省略，17sp，Sans-serif Medium）。未命名时显示“未命名会话”或“新会话”。
  - 副标题/状态行：居中或紧随标题的连接状态指示点（`· 已连接` / `· 正在重新连接…`，12sp，随状态着色）。
- **右侧**:
  - 上下文容量胶囊 (`ContextSeat`): 紧凑展示“`18%`”，点击弹出上下文各部分占用明细（系统提示词、工具列表、对话历史）。
  - 更多操作按钮 (`⋮`，48dp 触控区域): 弹出“新建会话”、“刷新”、“在浏览器中打开”（不提供“分享地址”功能以防凭据泄露）。

---

### 4.2 底部消息输入区域与键盘自适应 (Bottom Composer & Keyboard Policy)

#### 键盘弹起与滚动位置保护机制
- **保持阅读锚点 (Preserve Reading Position)**:
  - 当用户在向上翻阅旧消息历史时，软键盘弹起**不得自动跳跃滚回底部**，严密保持用户当前的视觉锚点与未读消息行。
  - **仅在以下两种情况自动吸附到底部**：
    1. 键盘弹起前，用户视口已经在最新消息附近（距底部距离 ≤ 56dp）；
    2. 用户明确执行了“发送”或“插队队列”动作后。

#### 运行中的输入与排队/干预能力 (Prompt Queue & Steer)
- **非单纯停止模式**:
  - 当任务处于运行状态（Running）时，**不剥夺用户的输入能力**。
  - 底部输入框依然允许输入草稿，发送区同时提供：
    1. **插队/排队发送 (Queue / Steer)**：支持向正在执行的 Agent 发送追加指令或插队排队。
    2. **停止任务 (Stop Task)**：以独立触控项或快速切换按钮呈现，方便随时中止失控任务。

#### 审批卡片弹出时的草稿保护
- 当智能体触发审批操作时，底部座位虽然切换为审批卡片展示，但**客户端必须在内存中完整保留用户的输入框草稿文本**。
- 审批被批准、拒绝、过期或在其他端处理完成后，输入框切回时草稿完整还原，绝不清空用户已敲入的内容。

---

### 4.3 智能体执行过程与实时流 (Agent Progress & Streaming)
针对长任务过程，客户端坚决摒弃“单调 loading 菊花”，采用透明化实时进度展示：

1. **思考过程折叠条 (`Think`)**:
   - 带有专属思考图标与动态发光文本：“深入思考中…” (`Deep diving…`)。
   - 运行计时器：超过 15 秒后自动显示运行时长（如 `24s`、`1m 12s`）。
   - 点击可展开查看详细思考推理内容，使用等宽浅灰色小字排版。
2. **工具调用实时卡片 (`Tool Call`)**:
   - 明确显示工具名称与执行状态（读取、写入、搜索、终端执行）。
   - 失败或终止时以醒目琥珀色/红色文字提示原因。
3. **打字机动态渐入 (Character Reveal)**:
   - 增量到达时平滑输出文字，最新字符带有半透明淡入微动效，防止长段落突兀跳动。
4. **待办任务清单折叠条 (To-dos Dock)**:
   - 紧贴输入框上方，显示统计（如 `3 completed · 1 in progress`）。
   - 点按展开展示具体任务事项与勾选状态，给用户明确的任务预期。

---

### 4.4 原生审批卡片系统 (Native Approval Card)
当智能体执行敏感操作（如运行 Bash 命令、修改核心文件）触发需要人工确认时，底部区域平滑过渡为原生审批卡片：

#### 卡片层级与视觉规范
- **外观**: 嵌入底部区域的警告边框卡片 (`rounded=20dp`)，带有 2dp 琥珀金边框高亮 (`#F59E0B`)。
- **顶部提示条**:
  - 左侧包含动态琥珀色呼吸光点与加粗标题：“等待审批” (`Waiting for approval`)。
  - 右侧显示时间或请求来源。
- **核心审批内容区 (最大高度 220dp，支持内部独立滚动)**:
  - 审批原因 / 描述（15sp，粗体清晰排版）。
  - 即将执行的命令或操作代码块（深色等宽代码衬底 `#18181A`，圆角 12dp，可复制）。
- **操作按钮组 (高度 48dp 规范触控区域)**:
  - **拒绝 (`Reject`)**: 次要操作，线框圆角按钮，文本为黑色/白色。
  - **允许一次 (`Allow once`)**: 主要操作，高对比度主填充按钮。

#### 审批状态转移细节
1. **等待审批中 (`waiting`)**: 按钮处于可点击态。
2. **提交中 (`submitting`)**: 用户点击任一按钮后，按钮立即置灰并显示“正在提交…”，防止重复点击导致并发错误。
3. **已被其他客户端处理 (`resolved-elsewhere`)**: 卡片平滑淡出并提示：“该审批已在其他端完成”，并在 1.5 秒内自动切回常规输入框并恢复草稿。
4. **已超时 / 已取消 (`expired`)**: 卡片提示：“此操作已取消或已过期”，允许用户点击关闭恢复对话草稿。

---

### 4.5 模型与预设选择器 (Model & Host-Advertised Effort)

- **动态强度列表 (Host Effort Roster)**:
  - 思考强度的选项列表必须**完全由服务端模型适配器所广播的可用列表动态渲染**（来自 Host 的 `efforts` 数组），**严禁在客户端写死 Off/Low/Medium/High**。若当前模型未广播任何推理强度选项，则界面不展示强度子菜单。
- **选项展示与容错**:
  - 当前选中项具备清晰勾选标识（`✓`）与高亮文字。
  - 若部分模型加载失败，红底展示提供方错误信息，并提供“点按重试”入口，不导致整个选择器白屏崩溃。

## 5. 暂不涉及的范围与系统边界 (Implementation Boundaries)

本阶段严格执行设计边界，以下特性明确**不在本轮设计范围内**（若用户涉及将引导至 Web 端完成）：
1. **插件管理器 (Plugin Manager)**: 保持现有 Web 访问方式。
2. **全功能交互式终端 (Interactive Terminal)**: 仅在聊天记录中展示结构化命令与结果，不内嵌虚拟终端仿真器。
3. **附件与多模态文件上传**: 本轮专注于核心文本、控制与代码会话。
4. **定时调度 (Schedules) 与自动化工作流**: 不在原生端提供编排界面。
5. **长任务目标编辑器 (Goal Editor) 与计划审阅 (Plan Review)**: 通过现有命令快速调用，不绘制重度定制图形化面板。
6. **复杂问答表单设计器 (Question Composer)**: 维持基础文本提示。
7. **架构迁移约束**: 坚决维持现有 Android Views 架构与 XML/Kotlin 代码契约，不引入 Jetpack Compose 依赖迁移。

## 6. 无障碍 (a11y) 与交互细节规范

- **无障碍标签 (`contentDescription`)**:
  - 所有图标按钮（菜单、发送、停止、审批展开）均强制赋予清晰的局部化无障碍描述（例如：“停止当前任务”、“选择模型，当前为 DeepSeek-V3”）。
  - 动态状态变化（如从“思考中”转为“等待审批”）通知无障碍服务 (`announceForAccessibility`)。
- **动态大字体缩放 (Dynamic Type)**:
  - 布局避免死高度设定，所有包含文字的容器采用 `WRAP_CONTENT` 或设定适配基准并留有弹性 padding，保证用户在系统设置 130%~150% 超大字号时不发生文本截断。
- **触控反馈 (Haptic & Visual Feedback)**:
  - 按钮包含 Material 3 标准涟漪 (`ripple`) 效果。
  - 关键操作（发送、点击允许审批）附带轻微原生震动反馈。
